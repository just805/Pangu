# 公网部署安全加固说明

> 2026-10-29（v0.3.85）。本文记录面向公网部署做的安全加固内容、部署方必须
> 配合的事项，以及已知的边界。

## 一、本轮加固了什么

| 项 | 内容 |
|---|---|
| 登录防爆破 | `/api/auth/login` 与 `/api/auth/init`：每 IP 10 分钟内失败 5 次 → 锁 15 分钟；全局 1 分钟 30 次失败 → 全局锁 5 分钟（兜底 XFF 伪造）；失败响应固定延迟 300ms 并记录来源 IP |
| 探活端点去指纹 | `/api/health` 只回 `{"ok":true,"status":"ok"}`——不再暴露 service 名与精确版本号（公网测绘最省事的 body 指纹）。版本查询走**鉴权的** `/api/version` |
| 改密码吊销会话 | 改密码成功即**轮换 JWT 签名 key**，全部旧 token 立即失效（此前泄露的 token 能用到 7 天自然过期） |
| 安全响应头 | `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`；`/api/*` 一律 `Cache-Control: no-store` |
| 移除 CORS 放行 | 前端与 API 同源部署，`Access-Control-Allow-Origin:*` 只有放宽跨站读取一个效果，已整体移除 |
| 认证面去产品名指纹 | 登录页/初始化页整体重做（居中单卡片、内联几何标记替代图片 logo、中性文案）；根路径 / 404 / 登录 / 初始化的文档标题改为「Console」；favicon 换为无可识别图案的中性图标。导出产物已验证：未鉴权可达页面 0 处产品名 |

**设计边界（刻意不做）**：登录后界面（已过鉴权）内的产品名、侧边栏 logo 保持不变——可见它们的前提是已经通过认证，不构成未鉴权指纹。

## 二、部署方必须配合的事项

1. **反代必须覆写 `X-Forwarded-For`，并把代理网段写进 `PANGU_TRUSTED_PROXIES`**（`proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;` + `PANGU_TRUSTED_PROXIES=127.0.0.1` 这类逗号分隔 IP/CIDR）。2026-11-17 起只有直连对端落在可信代理网段内才采信转发头——**不设置该变量时一律按 RemoteAddr 计**，反代后所有用户共享一个限流桶（更严，但防爆破去个性化）；设置错误网段同样拿不到真实客户端 IP。README 的 nginx 示例已包含覆写头。
2. **必须走 HTTPS**（nginx TLS 终结即可）。JWT 通过 `Authorization` 头与 `pangu_token` cookie 传输，明文 HTTP 上等于裸奔。
3. **强密码**：密码是公网部署唯一的认证边界（本系统可在服务器上执行命令）。最少 8 位是下限而非建议值。
4. **不建议在公网实例上配置真实目标的授权凭据**（资产 `auth` 字段）除非你接受该风险——拿到平台访问权的人能通过 `auth_request` 读到它们。

## 三、已知边界

- 限流是进程内存态：服务重启清零（影响的是攻击者的等待时间，不影响正确性）。
- 全局阈值能兜住 XFF 伪造，但分布式低速爆破（大量 IP 各打 4 次）在原理上无法被单机限流根治——公网实例建议额外套一层 WAF/CDN 限速。
- 未鉴权可达面：`/api/auth/*`（status/init/login/logout/change-password——change 自带 token 校验）、`/api/health`（已泛化）。已逐一路由核对，无其他豁免。

## 本轮新增/变更的公网相关行为

| 项 | 变更 |
|---|---|
| 会话载体 | token 收敛为 **HttpOnly cookie**（后端 login/init 下发），前端不再落 localStorage/可读 cookie——XSS 偷不走 7 天 JWT。`PANGU_COOKIE_SECURE=1` 加 Secure（TLS 部署必开） |
| SSE 认证 | `?token=` 通道**整体移除**（token 会进反代 access log/Referer）。EventSource 走同源 cookie 自动认证；第三方集成改走 cookie 或 Authorization 头 |
| 登录全局锁 | 触发条件加「≥5 个独立 IP」——单源攻击者只锁自己，管理员不再被反复 429；分布式爆破仍被兜住 |
| init 抢注 | 服务启动到管理员设密码之间，先到的公网访客可抢注管理员。`PANGU_INIT_TOKEN` 设置后 init 必须带 `X-Init-Token` 头（恒时比较）；未设置行为不变 |
| CSP | 静态前端响应新增 Content-Security-Policy（外域 script/连接全挡死）+ `frame-ancestors 'none'` |
| 校验和锚点 | selfupdate 的 SHA256SUMS 与发布包**分信道**下载（清单默认直连 GitHub），只劫持发布包信道的中间人无法伪造校验 |
| config.json | 启动时（Unix）自动把含 DB 口令的 config.json 收紧到 0600 |

## 安全相关环境变量速查

| 变量 | 默认 | 说明 |
|---|---|---|
| `PANGU_TRUSTED_PROXIES` | 空（不信任任何转发头） | 逗号分隔 IP/CIDR（如 `127.0.0.1,10.0.0.0/8`）。反代部署**必须设置**为代理网段，防爆破才按真实客户端 IP 生效 |
| `PANGU_INIT_TOKEN` | 空（不校验） | 设置后 `POST /api/auth/init` 必须带匹配的 `X-Init-Token` 头。公网部署建议：生成随机值注入，服务启动后从部署日志取 |
| `PANGU_COOKIE_SECURE` | 空 | `1` 时会话 cookie 加 `Secure`。经 HTTPS 部署必须开启（HTTP 下 Secure cookie 不发送，纯反代 TLS 终结场景同样适用） |
| `PANGU_HSTS_MAX_AGE` | 空（不下发 HSTS） | 如 `31536000`。确认站点长期走 HTTPS 后开启 |
| `PANGU_CHECKSUM_PROXY` | 空（校验和清单直连 GitHub） | GitHub 直连被墙的部署给 SHA256SUMS 指定独立代理；发布包下载仍走各自的 proxy 参数 |
| `PANGU_ALLOW_DOWNGRADE` | 空（禁止） | `1` 允许 hostd 自我换装降级（回滚演练用） |
| `PANGU_NOTIFY_ALLOW_LOCAL` | 空（拒绝） | 通知投递到环回/链路本地的逃生口（既有变量，列此备查） |
