# 行动安全（OPSEC）速查

## 与本平台的衔接

| 场景 | 用平台能力 |
|---|---|
| 出口隔离 | 平台 proxypool / 任务级出口代理；MITM 记录代理统一留痕 |
| 流量节奏 | `http_probe` 批量探活自带并发控制；`http_request` 单发可控 |
| 身份隔离 | `session_login` 按身份建 cookie jar；`auth_request` 用登记凭据组 |
| 被拦归因 | `graph_overview` 的 `guard_attributions`（ok/blocked/error + 最近样本） |
| 痕迹记录 | 所有请求进平台流量留痕；报告只引用真实记录 |
| 事实/复盘 | `record_fact` 写「被什么拦、换了什么打法」 |

## 核心原则

- **每个动作都要能解释来源**：授权范围内的测试流量也要低噪，避免误伤业务；
- **被拦先停手分析**，不要换 IP/换 UA 硬打——会扩大暴露面，也可能违反授权；
- 先读 `graph_overview.guard_attributions`：blocked 高说明目标在防，error 高说明工具/环境在坏。

## 身份与基础设施

- 不同任务/目标用不同出口与 UA，不混用身份；
- 测试流量走平台出口代理（proxypool）与 MITM 记录代理，不自建公网 C2；
- 不在目标上留可信长期后门（授权演练另有规则时从其规则）；
- 凭据只进运行时配置，不写进对话/报告明文。

## 流量节奏（按接口类型）

| 接口类型 | 建议 | 说明 |
|---|---|---|
| 静态资源/探活 | 可批量（`http_probe`） | 仍控制并发 |
| 登录/注册 | 串行，≥3s/请求 | 先查锁定策略 |
| 短信/验证码 | 少量（≤5 次） | 禁止轰炸 |
| 支付/订单 | 串行，最小样本 | 只验证一条 |
| 爆破/字典 | 仅授权明确允许 | 先查锁定策略，设上限 |

## 痕迹与日志

- 上传的工具/脚本记路径，任务结束前按授权要求清理；
- 不在目标写明文标记；必要标记用无害、可解释的文件名；
- 所有动作有流量/命令记录（平台自动留痕），报告只引用真实记录；
- 证据附件用 `save_evidence`，不要把敏感内容贴进对话。

## 检测信号与中止

立即暂停该类请求并写 `record_fact` 的现象：

- WAF 拦截页 / 403 骤增 / 连接被重置；
- 验证码升级、登录要求二次验证；
- 响应时间异常、返回蜜罐式数据；
- 收到蓝队/运营方告警或封禁通知。

处理：记录现象 → 换方向/换手法（不是换 IP 硬打）→ 上报操作者。

## 蜜罐识别

- 过于顺利的路径、异常开放的服务、与业务不符的数据；
- 返回结构完美但无真实业务字段；
- 先做最小只读验证，确认真实性再深入。

## 边界

- 演练规则优先于本速查；
- 不攻击授权外资产、不干扰生产、不做持久化后门；
- 发现真实数据泄露风险时立即停手并上报。
