# 0day 研究路径（授权范围内）

## 与本平台的衔接

| 场景 | 用平台能力 |
|---|---|
| 补丁/版本获取 | Bash `git`/`wget`；样本 `save_evidence` 归档 |
| 崩溃/异常样本 | `save_evidence`（输入文件、崩溃日志、环境） |
| 协议/HTTP fuzz | `http_request`（单发可控）+ Bash `ffuf`（字典筛选） |
| 带外验证 | `listener_start` + `listener_sessions`（SSRF/盲注/命令回显） |
| 版本/CVE 对照 | `search_vulns` / `get_vuln` / `get_poc` |
| 研究记录 | 每条假设/结果写 `record_fact`（失败也写） |
| 上报 | `report_finding`（附最小 PoC、受影响版本、根因） |

## 一、研究循环

```
观察异常 → 形成假设 → 最小验证 → 判影响面 → 记录/再迭代
```

- 每条假设写成一句话：「参数 X 未校验长度 → 堆溢出 → 崩溃」；
- 验证前先想好「什么结果算证实/证伪」，避免无限试；
- 失败也写 `record_fact`（假设、方法、结果），避免重复研究。

## 二、补丁差分（最快出洞路径）

1. 找旧版/新版（官网历史版本、Docker 镜像层、发行版补丁、GitHub tag）。
2. 比对：
   ```bash
   git log --oneline v1.0..v1.1
   git diff v1.0 v1.1 -- src/<关键目录>
   # 二进制
   radiff2 -C old new
   bindiff old new   # 需 IDA 插件
   ```
3. 看补丁改了什么校验（边界/权限/签名/编码）→ 反向构造未校验输入；
4. 本地起旧版验证崩溃/绕过，再在授权目标做最小验证。

## 三、行为异常线索

- 错误信息泄露内部路径/参数名（说明后端直接拼接）；
- 同一参数不同编码返回不同结果（解析差异）；
- 状态机跳步（跳过验证仍成功）；
- 时间差（越界/大对象处理慢）；
- 响应长度差异（截断/吞字节 → 解析器边界问题）；
- 内存/CPU 异常（可能 DoS，谨慎）。

## 四、Fuzz 最小化

```bash
# HTTP 参数筛选
ffuf -w payloads.txt -u "https://target/api?x=FUZZ" -mc all -fs <正常长度>
# 本地进程 fuzz（示例）
afl-fuzz -i in/ -o out/ -- ./target @@
```

- 抓真实请求为种子（HTTP/协议/文件格式）；
- 轻量优先：先小字典定位方向，再考虑 AFL/libFuzzer；
- 崩溃样本立即 `save_evidence` 并记录版本/环境/命令行；
- 生产目标不做大并发，单线程小字典足够定位。

## 五、崩溃分诊

- 可复现性：同输入多次是否稳定；
- 崩溃类型：读越界/写越界/空指针/断言（ASAN 输出）；
- 可控性：EIP/RIP 是否可控、能否读/写任意地址；
- 影响：崩溃=DoS（低价值）；越界读=信息泄露；可控写/执行=高危。

## 六、影响面判定

- 能崩 → 可能 DoS（低价值，谨慎）；
- 能读越界数据/绕过鉴权 → 高危；
- 能执行代码 → critical；
- 无法证明影响的异常 → 只写研究 fact，不报漏洞。

## 七、报告口径

- 附：触发条件、最小 PoC、受影响版本、根因（代码/反汇编片段）、缓解建议；
- 明确「未在真实业务数据上扩大验证」的边界；
- 复现步骤要让第三方能独立验证。

## 八、边界

- 只在授权目标/本地环境研究；不投放 0day 利用到生产；
- 不做会造成业务中断的 DoS 验证；
- 发现高危未修复漏洞时按流程上报，不公开细节。
