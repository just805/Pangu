# 小程序 43 类漏洞分类与验证口径

> 用法：先按「面」定位，再逐条看判据与最小验证。每条都要落 `record_fact` /
> `report_finding`，critical/high 必须有可复现请求或命令输出（机械证据）。
> 严重度是默认建议，最终按实际影响与证据分级。

## 验证纪律

- 每个漏洞至少两条相互印证的证据（请求响应 + 流量 ID / 双身份对照 / 可复现命令）。
- 越权类必须 A/B 双身份；只有一条响应不能证明越权。
- 注入类优先用差异/带外，不在生产做破坏性 payload。
- 否定结论也写 `record_fact`（「X 不可注入，依据 …」），避免后续重复劳动。
