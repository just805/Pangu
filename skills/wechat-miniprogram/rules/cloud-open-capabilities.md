# 云开发与微信开放能力专项

## 一、云开发 CloudBase

小程序云开发常见三类资源：云函数（callFunction）、云数据库（集合）、云存储（文件）。
客户端 SDK 会暴露环境 ID（`cloud.init({env})`）与函数名，`miniprogram_audit` 会抽取。

### 1. 云函数未授权（34）

- 从静态审计拿到函数名与 env；用抓包确认调用协议（HTTP 触发 / 微信云调用）。
- 去掉 token/openid，直接调 `callFunction`，看是否仍返回业务数据。
- 证据：请求（含 env、函数名、入参）+ 响应；证明「无凭据可调」。

### 2. 云函数越权（35）

- 同一函数用 A/B 两个 openid 调，函数内是否按 openid 过滤。
- 常见缺陷：函数信任入参里的 openid/userId；服务端直接 `where({_openid: event.openid})`。
- 证据：A 调出 B 的数据（点到为止，不批量）。

### 3. 云数据库未授权读写（36）

- 客户端直连集合（SDK 或 HTTP API），尝试 `get` 他人集合、`update/remove`。
- 只做**最小只读验证**：读一条非本人记录即可证明，不做批量导出/删改。
- 证据：查询条件 + 返回的一条记录（脱敏）+ 权限配置推断。

### 4. 云存储未授权/遍历（37）

- 文件 URL 是否可猜测/枚举；上传接口是否允许未授权上传或覆盖。
- 证据：文件访问回执 / 上传回执；不下载大量文件。

### 5. 环境隔离（38）

- 测试/生产是否共用 env、AppSecret、数据库；混淆环境会导致测试影响生产。
- 证据：env ID 对照 + 数据归属说明。

## 二、微信开放能力

### 1. code2session（39）

- 流程：`wx.login` 得 code → 服务端用 AppSecret 调 `jscode2session` 换 openid/session_key。
- 风险：AppSecret 泄露（第 3 类）可批量换 openid；code 可重放/无限流。
- 验证：用泄露的 AppSecret 换一次 openid（**仅一次**），证明可用即止。

### 2. 手机号解密（40）

- 小程序 `getPhoneNumber` 拿到 encryptedData+iv，服务端用 session_key 解密。
- 缺陷：解密接口不校验 code/session_key，允许解任意 encryptedData；或返回明文手机号给前端。
- 验证：用 A 的 code 解 B 的密文（若可控）或观察接口是否回传明文；只验证一条。

### 3. 订阅/模板消息（41）

- 消息内容、跳转链接是否可控；能否给非本人 openid 发消息。
- 验证：构造一次发送，确认内容注入或越权投递。

### 4. 支付 V3（42）

- 回调是否校验证书序列号/签名/金额；能否伪造 `TRANSACTION.SUCCESS` 通知。
- 验证：伪造回调后订单状态是否变为已支付（测试订单）；证据含回调体 + 订单状态。
- 金额篡改（14）与回调伪造（15）常同时出现，注意区分。

### 5. 调试/GraphQL/限流（43）

- 是否暴露 GraphQL 内省、Actuator、Swagger、调试接口；关键接口是否无限流。
- 验证：内省查询一次；限流只做少量探测，不做压测。

## 三、边界

- 云数据库/存储只做最小只读验证，不批量导出、不删改。
- code2session/手机号解密只做单次证明，不批量换票。
- 支付相关只在测试订单/测试环境验证；生产只做只读判断并记录。
