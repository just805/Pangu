# 小程序专项报告格式

> 与平台 Word/导出管线兼容：漏洞正文用 Markdown，证据引用平台 artifact / 流量 ID，
> 不要贴大段二进制或完整用户隐私数据。

## 章节结构

1. **测试概述**
   - 小程序名称、主体、版本/包哈希、测试时间窗
   - 授权范围与限制（明确哪些未测）
   - 测试方法：取包解包 + 静态审计 + 抓包 + 多身份接口测试 + 云开发/开放能力

2. **资产与接口清单**
   - 小程序包：文件名、哈希、解包文件数
   - 域名/接口：方法、路径、认证方式、角色、敏感返回字段
   - 云开发：环境 ID、云函数、集合、存储桶（脱敏）
   - 来源标注：静态审计 / 抓包 / 两者都有

3. **身份与权限矩阵**
   - 未登录 / A 普通用户 / B 普通用户 / 管理员
   - 每个接口在各身份下的可达性与数据范围

4. **漏洞清单（按严重度排序）**
   每条包含：
   - 标题、类别（对应 43 类编号）、严重度、CWE
   - 影响范围与前置条件
   - 复现步骤（最小请求/命令，可直接复制）
   - 关键响应/输出（脱敏）
   - 证据：流量 ID / artifact ID / A-B 对照
   - 修复建议（具体到校验点）

5. **云开发专项**
   - 云函数未授权/越权、数据库/存储未授权、环境隔离
   - 与第 4 章漏洞去重，只补充云侧特有结论

6. **开放能力专项**
   - code2session、手机号解密、订阅消息、支付回调、调试/限流

7. **攻击路径（如有）**
   - 从「硬编码 AppSecret / 未授权接口」到「越权读数据 / 伪造支付」的链路
   - 每步引用对应漏洞编号与证据

8. **修复优先级建议**
   - 立即：支付回调、AppSecret 泄露、云数据库未授权
   - 高优：越权、未授权 API、手机号解密
   - 中低：信息泄露、CORS、限流

9. **附录**
   - 接口全量清单
   - 证据附件索引（artifact ID → 说明）
   - 未完成项与原因

## 写作要求

- 每个 critical/high 必须能按「复现步骤」独立复现；缺证据的降级或标注待验证。
- 越权必须写清 A/B 身份与具体资源 id（脱敏后保留可核对特征）。
- 用户隐私数据只保留证明所需的最小片段（如手机号中间四位打码）。
- 否定结论也进附录（「已测但不可注入」），体现覆盖度。
