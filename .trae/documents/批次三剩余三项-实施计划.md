**`server/task_llm.go`**
- 在 worker 装配处（约 L725-731 同块）接线：
  ```go
  if taskNum, perr := strconv.ParseInt(t.ID, 10, 64); perr == nil && taskNum > 0 && s.m.pg != nil {
      pg := s.m.pg
      wk.SetToolPerf(func() []agent.ToolPerfHint {
  ```

- 非 worker 角色被过滤。

### 改动
**新增 `server/task_budget.go`**
- 设置键：`task_budget_tokens`（0=关闭，范围 1_000_000–500_000_000）、`task_budget_warn_pct`（默认 80，范围 50–95）。
- `type taskBudgetConfig struct { Enabled bool; Tokens int64; WarnPct int }` + `taskBudgetFromPG(pg)`（读库失败回默认、绝不硬故障）。
- `func (e *Engine) checkTaskBudget(t *Task) bool`：
  - `t.Store.TokenTotal()` → `total = Input+Output`（与 intent 级预算口径一致）。

  - 硬阈值 `tokens`：`t.requestSettle("auto_budget", detail)` 并返回 `true`。

**`agent/planner.go`** `renderTriggers` 增 `case "budget": b.WriteString("\n- "+ev.Detail)`（与 coverage_gap/depth_gap 同款，确定性引擎提醒）。

**`server/auto_finish.go`** `maybePendingSettle`：把 `if reason != "auto_rounds"` 改为 `reason != "auto_rounds" && reason != "auto_budget"`（预算硬闸可在有在跑意图时收尾，settle 内部会 drain + grace 硬取消）。

**`server/engine_timeout.go`** `settleTaskWithReason` switch 增 `case "auto_budget": label = "自动收尾：" + detail`（并入现有 `auto_idle/auto_coverage/auto_rounds` 分支即可）。
> 说明：`suppressAutopilotSettle` 不包含 auto_budget，因此自主推进不会抑制预算硬闸——这是成本硬上限，符合预期。终态沿用 `settleTerminalStatus`：目标未全达成记 timeout（未完成），不谎报 done。

**`server/server.go`** GET 设置返回 `task_budget_tokens` / `task_budget_warn_pct`；PUT 请求体加同名字段 + 范围校验（tokens 0 或 1M–500M；warn 50–95）。

## 3. 上下文分层 + 价值评分（b3-context，最小版）

### 现状（已具备，不重复建设）
- 态势体积治理：`relatedOverviewTotalTextRunes` / `overviewTextBudget`（[agent/tools.go](file:///d:/xm-v0.1.0/Pangu/agent/tools.go#L894-L949)）。
- 冷区折叠 `cold_digests` + 按需 `expand_digest/node_detail`。
- 回归看门狗：autopilot 停滞唤醒（[server/autopilot.go](file:///d:/xm-v0.1.0/Pangu/server/autopilot.go#L116-L181)）+ auto_finish 连续零新增收尾（[server/auto_finish.go](file:///d:/xm-v0.1.0/Pangu/server/auto_finish.go#L94-L114)）。
- 概览已带 `direction_report`（tokens/yields 产出率）与 `stall` 块。

### 改动（只补价值评分驱动的截断）
**`agent/tools.go` 新增纯函数 `factValueScore(n *db.Node, fromIntent int64, yieldsOf, tokens) int`**
- 基础分：`confirmed` > `inferred`/缺失 > `低新颖度`（读 payload `confidence`）。
- 有 `evidence`（payload 非空）加分。
- 产出它的意图 `yields>0` 加分；该意图 tokens 过高但自身零下游则减分（避免昂贵噪声）。
- 是 finding 关联（`factFrom` 命中 finding）加分。

**`graphOverviewData` 的 `recent_facts` 选择**：由「纯最新 20 条」改为「先按 valueScore 保底 Top-K（如 8 条高价值），其余名额按最新补齐」，去重后仍 ≤20。`recent_done_intents` 同理：先保留 `yields>0` 的高价值意图，再按最新补足 12 条。
- 只在超出 cap 时触发重排；正常规模（≤cap）行为不变，避免无谓抖动。
- 不新增返回字段语义（保持向后兼容），仅在注释说明选取策略。

**测试 `agent/tool_value_score_test.go`**
- confirmed+evidence 得分高于 inferred 无证据。
- 选择器：高价值旧事实能在截断中保留，低价值新事实被挤出。
- 规模未超 cap 时顺序与旧行为一致。

> 说明：不新增独立「价值评分 watchdog」后台协程——本地已有 autopilot 停滞看门狗与 auto_finish 幂等收尾，再叠一层会造成双重催促/提前收尾；价值评分只作为态势截断的排序依据（正是上游 0.4.106 的核心意图），改动小且可测。
