# 微信小程序渗透能力 — 实施计划

## Context

平台已有通用 Web/API 渗透底座（抓包 MITM、`http_request`/`session_login`/`auth_request`、
`js_audit`、`report_finding`、证据/流量绑定），但缺少小程序的场景化能力：
wxapkg 取包解包、小程序登录态（code2session / openid / 加密手机号）、云开发
（云函数/数据库/存储）与开放能力测试、43 类小程序漏洞分类、清单与报告格式。

目标：以「**技能包 + 脚本 + 原生 Go 工具**」三件套落地，让 planner 会定方向、worker
会用工具、reporter 能出小程序专项报告。所有能力复用既有抓包/HTTP/证据/报告管线，
不新造重复底座。

落地形态用户已确认：全量（技能包 + scripts + 原生 Go 工具）。

### 43 类漏洞分组（写入 vuln-taxonomy-43.md，逐条给验证与证据口径）

- 资产与源码（1–5）：源码包泄露、sourcemap/调试信息、硬编码 AppSecret/密钥、内部接口暴露、组件/依赖 CVE。
- 认证与会话（6–12）：未授权 API、水平越权、纵向越权、IDOR、JWT/Token 缺陷、登录态伪造、验证码/短信轰炸。
- 业务逻辑（13–19）：密码重置、支付金额篡改、支付回调伪造、订单越权、优惠券/积分、退款/状态机、竞态。
- 注入与解析（20–27）：SQL、NoSQL、命令、模板、XXE、SSRF、文件上传/路径穿越、开放重定向。
- 前端与传输（28–33）：XSS（web-view/H5）、CSRF、CORS、敏感数据明文传输、弱加密/自定义加密、WebSocket 未授权。
- 云开发（34–38）：云函数未授权、云函数越权、云数据库未授权读写、云存储未授权/遍历、环境隔离缺失。
- 开放能力（39–43）：code2session 滥用、手机号解密接口滥用、订阅/模板消息注入、支付 V3 回调/证书、GraphQL/调试接口/限流缺失。

> 具体 43 条在实现时编号落表；每条含「判据 + 最小验证 + 证据要求 + 建议严重度 + CWE」。

## 2. 原生 Go 工具：`agent/tools_miniprogram.go`

两个领域工具，构造期不解引用 store（nil 安全），供 seed 目录读取 Name/Desc/Schema：

### 2.1 `miniprogram_unpack`（writeTool，非并发）
- 入参：`input_path`（.wxapkg，绝对路径或相对 runDir）、`output_dir`（可选；默认
  `<runDir>/miniprogram-unpack`，runDir 为空时默认 `<os.TempDir()>/pangu-miniprogram`）。
- 输出：`{files, total_bytes, output_dir, app_config?, project_config?, sourcemaps?}`（文件清单截断）。
- 格式实现（wxapkg v1，标准包）：
  - 14 字节头：`0xBE`、info1、indexInfoLength、bodyInfoLength、`0xED`；14 起 4 字节 fileCount；
    随后 each：nameLen、name、offset、size。
  - **加密兼容**：对 name 字节按 0–255 逐 key 试解，用「全部 name 以 `/` 开头 + offset/size
    落在文件范围内 + 无重复」做自校验，命中即采用；data 用同一 key 解 XOR。
  - offset 解释：绝对值在范围内则用绝对；否则按 `dataStart+offset` 解释（兼容两种实现）。
  - 安全上限：文件数 ≤ 20000、单文件 ≤ 64MB、总解压 ≤ 512MB、name 长度 ≤ 4096、拒绝 `..` 路径穿越。
  - 不支持的变体（APP_V2/分包子包等）返回明确错误，提示改用 `wxappUnpacker`/`unveilr`，不静默产出空目录。
- 单测：合成 plain 与 XOR(key=0x5A) 两种 .wxapkg fixture，断言文件内容与路径正确；路径穿越被拒。

### 2.2 `miniprogram_audit`（readTool，并发）
- 入参：`path`（解包目录或单个文件）、`max_files`（默认 5000）、`max_file_bytes`（默认 2MB）。
- 输出 JSON：`endpoints[]`、`secrets[]`（类型/文件/行号/命中片段脱敏）、`appids[]`、
  `cloud{envs[],functions[]}`、`sourcemaps[]`、`sensitive_params[]`、`hints[]`（映射到 43 类）。
- 特征：`https?://`、`wx.request/uploadFile/downloadFile`、`wx.cloud.callFunction`、
  `cloud.init({env})`、`baseURL`、`/api/`、`AppSecret|appsecret|AKID|SecretKey|accessKey|Bearer|-----BEGIN`、
  `sourceMappingURL`、`.map`、`openid|unionid|session_key|encryptedData|iv`。
- 上限：endpoints ≤ 200、secrets ≤ 100，避免撑爆上下文。
- 单测：临时目录放含硬编码 appsecret、云环境 id、接口与 sourcemap 的样本，断言分类与去重。

## 6. 边界与风险

- wxapkg 变体多：v1 标准包全支持；V2/分包明确报错并给出外部工具路径，不假装成功。
- 所有测试仅针对授权目标；SKILL.md 与 rules 明确「不碰生产数据、不做破坏性操作」。
- 原生工具只做本地解包/静态审计，不发网络请求；云开发/开放能力测试全部走既有
  `http_request`/`session_login`，数据留痕口径不变。
